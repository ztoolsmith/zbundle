# zbundle

[![CI](https://github.com/ztoolsmith/zbundle/actions/workflows/ci.yml/badge.svg)](https://github.com/ztoolsmith/zbundle/actions/workflows/ci.yml)

A JavaScript/TypeScript bundler written in **Zig**, built on
[zcompiler](../zcompiler) (the compiler) and [zignapi](../zignapi) (the Node
bridge).

`zbundle.bundle(entry)` returns a single executable JS file (ESM) containing
**only the code reachable from the entry**. It works by **scope hoisting**: every
module is merged into one scope, and collisions are resolved by renaming. No
function wrappers, no runtime module registry — just flat, readable JS.

> Importing 1 function from a 20-function barrel: **24 modules / 4022 B → 3 modules / 260 B**.

```bash
zbundle src/index.tsx -o dist/bundle.js
```
```
✔ dist/bundle.js  3 modules  0 externals  −80 statements, −21 modules
  4022 → 260 bytes (6 %) in 2.5 ms  esm
```

…or from Node:

```js
import zbundle from "zbundle";

zbundle.bundle("src/index.tsx"); // -> a JS string
```

```js
// Generated by zbundle — ESM, single file.
import { jsx } from 'react/jsx-runtime';

// ── lib/math.js ──
const helper = (n) => n;
const add = (a, b) => helper(a) + helper(b);

// ── format.js ──
const helper$1 = (k) => `[${k}]`;          // collision renamed
const format = (k, v) => `${helper$1(k)} ${v}`;

// ── main.js ──
console.log(format('add', add(2, 3)));
```

The judge: **the bundle runs in Node and says exactly what the original project
says** (`playground/run.mjs`) — the bundler's round-trip.

## What it does

- **Resolve** relative specifiers: omitted extensions
  (`.ts` → `.tsx` → `.js` → `.jsx` → `.mjs`, in that order), directory
  resolution (`./utils` → `utils/index.ts`), canonical paths (symlinks, case).
- **Traverse and order**: each module once, emitted after its dependencies
  (post-order DFS); cycles detected and handled.
- **Compile upstream**: TypeScript erased, JSX lowered to `jsx()/jsxs()` — the
  whole zcompiler chain, before linking.
- **Link**: `import`s vanish (they are name aliases), re-export chains resolve
  down to the originating binding, namespaces (`import * as ns`) are
  materialized and deduplicated, externals are hoisted and merged at the top,
  and the entry's exports are the only survivors.
- **Shake**: emit only what is reachable. Roots are top-level side effects (an
  imported module *is* evaluated) and the entry's exports; everything else has
  to earn its place. The purity rule is explicit and conservative — **when in
  doubt, impure**: a bundle 5 % larger is one bug fewer.
- **Refuse clearly** what it cannot do honestly (see below).

## The command

```
zbundle <entry> [-o <file>]      bundle (statistics go to stderr)
  -f, --format esm|iife          iife: everything in an IIFE, needs zero externals
      --dead                     list what tree-shaking removed
      --graph                    the module graph, without bundling
      --watch                    rebuild on change (requires -o)
      --quiet                    no statistics
```

A refusal exits with **code 1** and its explanation, and writes **nothing** to
stdout — a pipe never receives invalid JS.

## Getting started

```bash
pnpm install
pnpm build     # the addon and loader, then the CLI (tsc)
pnpm test      # node --test

node playground/run.mjs                           # THE JUDGE
node playground/inspect.mjs barrel --run          # read a bundle, and run it
node playground/inspect.mjs shake-diamond --dead  # what shaking removed
```

Requirements: Zig **0.16.0**, Node ≥ 18, and the `zignapi` and **`zcompiler`
≥ 0.3.0** repositories cloned alongside (zbundle references them as siblings).

## Limitations

| refusal | why |
|---|---|
| top-level await | would make the whole bundle asynchronous |
| `import.meta` | depends on the module URL, which no longer exists after merging |
| `import()` of an **internal** module | needs a separate chunk → code splitting |
| live binding via a **namespace object** | the object is a snapshot: it would freeze the value |

A live binding imported **by name** (a reassigned `export let`) does work: after
merging, the importer references the very same variable.

**`node_modules` is not resolved yet** — package imports become externals and
stay in the bundle. zbundle builds libraries, not applications, for now.

## Roadmap

- **next** — cross-module minification (zcompiler's mangler already exists), then
  source maps.
- **after** — `node_modules` (real package resolution, and the `sideEffects`
  field that comes with it) and code splitting (`is_dynamic` edges are already in
  the graph).
- **later** — top-level await, intra-statement granularity.
